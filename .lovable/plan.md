# ABox Phase 52 / Batch B2 — Typography Numeric Verification Tolerance Adjustment (PLAN ONLY)

## 1. Current state

The B2 typography collection `ABox/Typography` already exists correctly in Figma with the approved 19 variables (9 STRING + 10 FLOAT), the right names, types, aliases, source descriptions, and B1 untouched. The only remaining failure is the FLOAT production-value comparison inside `verifyB2()`.

Observed real-Figma deltas for the three non-binary-representable values are:

| Variable | Expected | Stored | Delta |
|---|---|---|---|
| role/heading/letter-spacing | -2.7999999999999998224 | -2.7999999523162841797 | 4.768e-8 |
| role/display/letter-spacing | -3.2000000000000001776 | -3.2000000476837158203 | 4.768e-8 |
| role/display/line-height | 1.0200000000000000178 | 1.0199999809265136719 | 1.907e-8 |

The current `FLOAT_EPSILON = 1e-9` in `verifyB2()` is below the actual Figma storage jitter, so the comparison still fails for those three variables. The jitter is a pure IEEE-754 round-trip artifact, not a production-value error.

## 2. Exact change

Only the tolerance constant and its documentation change.

### 2.1 `tools/figma-plugin/plugin.js` — `verifyB2()`

Around line 1008, replace:

```js
  // FLOAT comparison uses a 1e-9 tolerance. Figma round-trips a stored FLOAT
  // through its own numeric representation, so values that are not exactly
  // representable in binary floating point (-2.8, -3.2, 1.02) can come back a
  // few ulps away from the JS literal that was written. The tolerance is far
  // smaller than any meaningful typographic difference, and every comparison
  // is printed at full precision below, so a real mismatch cannot hide.
  const FLOAT_EPSILON = 1e-9;
```

with:

```js
  // FLOAT comparison uses a 1e-7 tolerance. Figma round-trips a stored FLOAT
  // through its own numeric representation, so values that are not exactly
  // representable in binary floating point (-2.8, -3.2, 1.02) can come back a
  // few ulps away from the JS literal that was written. The largest observed
  // real-Figma delta is ~4.8e-8; 1e-7 is safely above that while remaining many
  // orders of magnitude below any meaningful typographic difference. Every
  // comparison is printed at full precision below, so a real mismatch cannot hide.
  const FLOAT_EPSILON = 1e-7;
```

Leave `floatMatches(stored, expected)`, the per-variable evidence printing, the failure labelling, the type-count checks, the structural checks, the alias checks, and the Light/Dark parity check otherwise unchanged. The parity check already uses `FLOAT_EPSILON`, so it will automatically inherit the widened tolerance.

### 2.2 `tools/figma-plugin/README.md` — B2 tolerance paragraph

Around line 189, replace the existing `1e-9` paragraph with an equivalent `1e-7` paragraph referencing the observed ~4.8e-8 max delta.

### 2.3 Generated artifact

`tools/figma-plugin/code.js` must be regenerated by `node tools/figma-plugin/build.mjs` because `plugin.js` is concatenated into `code.js` at build time. No manual edits to `code.js`.

## 4. Tolerance justification

The selected tolerance is `1e-7`.

- The largest observed real-Figma storage delta is `4.768e-8`, so `1e-7` gives a safe margin of roughly 2×.
- It is still ~10 million times smaller than the smallest meaningful typographic value in the set (size `10` px). A real token error such as a mis-typed `10` vs `11` px or `-2.8` vs `-3.2` would produce deltas of `1` or `0.4`, far above the tolerance.
- The evidence block continues to print expected values, stored Light/Dark values, and exact deltas at full precision (`toPrecision(20)` and `toExponential(3)`), so any future mismatch larger than `1e-7` is still explicitly named.
