# Batch B7 — Shells & shared page composition

## What already exists

B7 is already extracted and implemented in the plugin layer from the production shells; it
has never been able to run in Figma. `tools/figma-plugin/tokens-b7.js` (generated by
`extract-b7.mjs`) holds the approved, source-backed definition, `plugin.js:3775-4479` holds

So B7 needs no new shell design work. It needs the same dynamic-page async correction B6
required, plus a guarded rollback, before Create can run.

## The fix required before B7 can run

### 1. Dynamic-page async corrections (`plugin.js`, B7 range only)

`manifest.json` sets `"documentAccess": "dynamic-page"`, which forbids the synchronous style
setters and `instance.mainComponent`. Full audit of lines 3775-4479 found exactly these:

| line | current | replacement |
| --- | --- | --- |
| 3842 | `node.fillStyleId = …` | `await node.setFillStyleIdAsync(…)` |
| 3845 | `node.strokeStyleId = …` | `await node.setStrokeStyleIdAsync(…)` |
| 3850 | `node.effectStyleId = …` | `await node.setEffectStyleIdAsync(…)` |
| 3868 | `node.textStyleId = style.id` | `await node.setTextStyleIdAsync(style.id)` |
| 3876 | `node.fillStyleId = …` | `await node.setFillStyleIdAsync(…)` |
| 3971 / 4027 / 4081 | `root.fillStyleId = …` (Internal, Marketplace variant, Member) | `await root.setFillStyleIdAsync(…)` |
| 4277 | `const main = inst.mainComponent` in `b7MainName` | `await inst.getMainComponentAsync()` |
| 4287 | `c.mainComponent` twice in `b7NestedComponentIds` | `await c.getMainComponentAsync()` |

Consequent signature changes: `b7Frame` becomes async (it is the only sync style writer), and
`b7Pill`, `b7MainName`, `b7NestedComponentIds` become async; every call site inside
`b7Build*`, `b7Ensure*`, `b7Nodes`/`b7Refs` and `verifyB7` gets `await`, with `for…of` loops
where an `Array.map`/`filter` callback would otherwise swallow a promise. Nothing else in the
range is dynamic-page incompatible: `setProperties`, `loadFontAsync`, `combineAsVariants`,
`b4Style` index reads and `b4FindSet`/`b4FindComponent` lookups are all legal, and every
entry point already calls `loadAllPagesAsync()`.

### 2. Guarded rollback and partial-build cleanup

B6 proved a half-built component can survive a mid-build throw. B7 gets the same two-part
protection, modelled exactly on `b6Guarded` / `b6CleanupIncompletePatterns`:

- `b7Guarded(page, fn)` wraps each per-shell build. It snapshots the page children before the
  build and, on throw, removes only nodes that are new in that run **and** whose name is an
  approved B7 shell name or an approved `variant=…` node name. It never touches a
  pre-existing node and never touches a `COMPONENT_SET`.
- `b7CleanupIncompleteShells()` — a new guarded command plus a "Remove incomplete B7 shell
  nodes" button. It removes a top-level node on `03 Shells` only when every condition holds:
  parent is the page; name is an approved B7 shell or approved orphan variant name; the node
  fails `b7HasRequiredShape` for its approved region list (provably incomplete, so a complete
  shell can never qualify); `getInstancesAsync()` reports zero instances. Anything failing a
  condition prints `KEPT — <reason>` with its live vs expected region list and is left alone.

Nothing on `01 Components`, `02 Patterns` or any other page is ever considered.
