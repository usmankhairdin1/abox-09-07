## Root cause

Same class of stale batch-local page assertion already corrected in B0, B4, B5 and B6. The allowance list was grown incrementally (01 Components, 02 Patterns, 03 Shells, then 04 Experiences, plus a hand-written B10 special case) but **05 Screens was never given an allowance** — it still demands that page be empty.

In the final library 05 Screens legitimately holds 179 approved B9 frames. 00 Foundations is empty, 06 Documentation passes its special case, and the four `writable` pages are skipped wholesale, so every offender comes from 05 Screens. The inner loop breaks at `b7PageEvidence.length >= 40`, and the assertion prints the evidence-buffer length, so the reported **40** is the cap, not a true count — all 40 listed lines are approved B9 screen frames.

Secondary defects in the same block: the four `writable` pages get no identity check at all (a stray or renamed node there is invisible to B7), and the count in the label is the buffer size rather than the real offender total.

All other B7 checks pass: shell inventory, object types, property/layer bindings, component-property references, responsive and interaction audits, limitation and count checks, idempotency, and the B0–B6 preservation checks at 4910–4934.

No new inventory source, no generic allowance; the `B10_PAGE`/`b10ApprovedNames()` special case is dropped because the helper already maps 06 Documentation to the approved B10 documents.
