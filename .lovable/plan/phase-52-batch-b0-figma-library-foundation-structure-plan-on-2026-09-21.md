# Phase 52 — Batch B0: Figma Library Foundation Structure (PLAN ONLY)

Scope: create the seven library pages, nothing else. No variables, no text styles, no components, no variants, no publishing.

## A. Target-file requirement

`ABox Proof — Scratch` stays the proof file and is NOT repurposed.

Before execution the user creates one new, empty Figma Design file named exactly:

```text
ABox Design System — Library
```

Requirements: same team as the proof file, user has Can edit, file otherwise empty (only Figma's default `Page 1`).

Separation is enforced in code, not by convention: the plugin reads `figma.root.name` and refuses to run B0 unless it equals `ABox Design System — Library`. Running it in `ABox Proof — Scratch` stops with `STOP: wrong target file`. The proof action is given the mirror-image guard, so the proof can only run in the scratch file. Neither file can be mutated by the other batch.

## B. Exact plugin implementation changes required

All changes live in `tools/figma-plugin/` only.

- `tokens.js` — add a `library` block: `targetFileName: "ABox Design System — Library"`, `proofFileName: "ABox Proof — Scratch"`, and the ordered `pages` array (section D).
- `plugin.js` — add:
  - `requireFile(expectedName)` — throws STOP when `figma.root.name !== expectedName`; called at the top of both the proof handler and the B0 handler.
  - `ensureLibraryPages()` — idempotent page reconciliation (section D).
  - `verifyLibraryPages()` — structural checks (section E), printing `RESULT: B0 PASSED` or `RESULT: B0 FAILED`.
  - New message types `b0-run` and `b0-verify`; existing `run`/`verify` untouched in behaviour.
- `ui.html` — add two buttons, `Create library pages` and `Verify library pages`, alongside the existing proof buttons.
- `manifest.json` — unchanged.
- `code.js` — regenerated by `node tools/figma-plugin/build.mjs`; never hand-edited.
- `README.md` — document the two-file model and the B0 run steps.

## C. Exact seven-page creation sequence

Names and order are literal and final:

```text
1  00 Foundations
2  01 Components
3  02 Patterns
4  03 Shells
5  04 Experiences
6  05 Screens
7  06 Documentation
```

Sequence per run:

1. `requireFile("ABox Design System — Library")`.
2. Read `figma.root.children` (existing pages).
3. For each name in order: reuse the first existing page with that exact name, otherwise `figma.createPage()` and set the name.
4. Reorder: `figma.root.insertChild(index, page)` for index 0..6 so the seven appear in the order above, ahead of any other page.
5. If Figma's default `Page 1` still exists, is empty, and is not one of the seven, remove it. A non-empty stray page is never removed — it is reported as `UNEXPECTED PAGE` and the run fails.
6. Run `verifyLibraryPages()`.

No node is created on any page. The pages stay empty by design.

## D. Idempotency strategy

- Match strictly by exact page name; never by index or position.
- Create only when no page of that name exists; otherwise reuse the node (page id stable across runs).
- If two or more pages share one of the seven names, the run stops with `DUPLICATE PAGE` rather than guessing which to delete.
- Reordering is applied every run, so a manually dragged page is corrected in place.
- Page ids are printed on every run so run-1 and run-2 ids can be compared byte-for-byte.
- No variables, styles, components or content are touched by the B0 path at all.

## E. Native Figma validation checks

`verifyLibraryPages()` asserts, all must PASS:

1. File name equals `ABox Design System — Library`.
2. Every one of the seven names exists, with count exactly 1 each.
3. Each is a real `PAGE` node (`node.type === "PAGE"`).
4. Their indices in `figma.root.children` are 0..6 in the listed order.
5. No unexpected extra pages, or if present, they are listed and the check fails.
6. Zero local variable collections, local text styles, local effect styles and components created by this batch — the count is reported and must be 0 in the fresh library file.
7. No IMAGE fills and no flattened nodes anywhere in the file.

Failure prints `RESULT: B0 FAILED` and stops; no partial success is claimed.

## F. Execution evidence required in the FINAL REPORT

1. Target file name and confirmation of edit access.
2. Verbatim full plugin output for run 1.
3. Run-1 page inventory: the seven names, their ids, their indices.
4. Verbatim full plugin output for run 2.
5. Run-2 inventory with identical ids and indices — proving update in place, no duplicates.
6. Confirmation that page count is exactly 7 and no stray pages remain.
7. Confirmation that the library file contains 0 variables, 0 styles, 0 components.
8. Confirmation that `ABox Proof — Scratch` was not opened or modified during B0, and that its proof objects (1 variable, 1 text style, 1 component set, 2 variants, `tone` property) are intact on a later verify-only run in that file.
9. Explicit statement that the library was NOT published.
10. The final `RESULT: B0 PASSED` line, or the exact failure text.

No file under `src/**`, no route, asset, token, branding, governance or production/reference UI file is modified by this batch. The only files changed on approval are inside `tools/figma-plugin/`. `git diff --stat -- src/` must be empty afterwards, and the locked Phase 49 hashes must be unchanged.
