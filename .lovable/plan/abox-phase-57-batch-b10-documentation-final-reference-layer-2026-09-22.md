## Pre-run plugin corrections required

The B10 section predates the dynamic-page async conversions applied in B7/B8/B9 and will
fail at runtime as written. The smallest corrections, mirroring the approved B8/B9 fixes:

1. **Async region/child frames.** The eight `b7FrameLegacy(...)` call sites inside the B10
   builders (6089, 6097, 6099, 6106, 6119, 6130, 6138, 6144) use synchronous
   `fillStyleId` / `strokeStyleId` / `effectStyleId` setters, which throw in dynamic-page
   documents. Switch them to `await b8Frame(...)` (the existing async twin, already used by
   B8 and B9) and make `b10ReferenceRegion`, `b10RowNode`, `b10SectionNode`,
   `b10SectionsRegion`, `b10EvidenceRegion` await accordingly. **`b7FrameLegacy` itself
   stays in the file, unmodified**, per the preservation requirement.
2. **Async root setters** in `b10BuildFrame` (6164–6165):
   `await root.setFillStyleIdAsync(...)`, `await root.setStrokeStyleIdAsync(...)`.
3. **Guarded rollback**: add `b10Guarded(page, label, fn)` mirroring `b8Guarded`/`b9Guarded`
   and wrap the create path in the handler as
   `await b10Guarded(b10Page(), "Batch B10 — documentation", ensureB10Documentation)`, with
   `verifyB10()` staying outside the guard so a verification failure never deletes frames.
4. **Handler preload**: `await figma.loadAllPagesAsync();` before `b10Page()` in the
   `b10-run` branch, matching B8/B9.

No other B10 logic, and no signature, region, placement, reference or counts contract
change. No B0–B9 logic is modified.
